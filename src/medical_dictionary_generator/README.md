# Medical Spellcheck Generator (`medical_spellcheck`)

Generates a **supplemental** medical spellcheck dictionary (`medical.dic` +
`medical.aff`) for [Hunspell](https://github.com/hunspell/hunspell) / MySpell,
as used by LibreOffice and OpenOffice. The word list is parsed from the
**UMLS / RxNorm Metathesaurus** (`MRCONSO.RRF`) and is designed to sit
**alongside** the base English dictionary (`en_US.dic` / `en_US.aff`), not to
replace it.

The end goal is a clinically focused list: terms a clinician might actually use
in dictation, with codes, abbreviations, systematic chemical names, biological
sequences and base-English words stripped out.

---

## Files

| File | Purpose |
| --- | --- |
| `main.py` | The whole generator pipeline (parse → filter → de-dup → collapse → write). |
| `enums.py` | UMLS field enumerations (`UMLSLanguageOfTerm`, `UMLSTermAbbreviation`, `UMLSSuppresssFlag`, etc.). |
| `models.py` | `MetathesaurusConcept` dataclass — one parsed `MRCONSO.RRF` row. |
| `test_main.py` | Unit tests for parsing, filtering (incl. `SAB` + organism), word extraction, affix expansion, de-dup, case/hyphen collapsing and the must-have safety net. |
| `dictionaries/medical.dic` | **Generated** output: the medical word list (first line = word count). |
| `dictionaries/medical.aff` | **Generated** output: the companion affix file (see below). |
| `dictionaries/en_US.dic` / `en_US.aff` | The base English dictionary, used as a **reference** for de-duplication only. Not generated by us. |

> The generator also reads **`MRSTY.RRF`** (the UMLS semantic-type file) from
> the same `META` folder to drop taxonomy/organism concepts. See *Quirks*.

## Running the generator

Requires Python ≥ 3.14, no third-party dependencies.

```powershell
# Full run with defaults (reads MRCONSO.RRF from UMLS_LOCATION in main.py)
python main.py

# Useful flags
python main.py --umls-location "D:\path\to\META" --output-dir ".\dictionaries"
python main.py --limit 20000          # only read first N records (fast test)
python main.py --exclude-dic ""       # disable de-dup against en_US
python main.py --keep-hyphenated      # keep redundant hyphenated compounds
python main.py --keep-case-variants   # keep Cytokine/CYTOKINE alongside cytokine
python main.py --keep-plurals         # keep explicit plurals instead of singular/S forms
python main.py --keep-genitives       # keep explicit "'s" forms instead of base/M forms
python main.py --no-must-have         # don't re-add the curated clinical terms
python main.py --mrsty-file ""         # disable the organism/taxonomy filter
python main.py --include-sab all      # accept ALL sources (huge list)
python main.py --include-sab "SNOMEDCT_US,RXNORM,MSH"  # custom source set
python main.py --include-licensed     # ALSO add SNOMED CT + MedDRA (see licensing)
python main.py --rxnorm-location "D:\path\to\rxnorm\rrf"  # add standalone RxNorm (RXNCONSO.RRF)
```

> ⚖️ **Licensing:** by default the generator keeps only freely redistributable
> sources (`RXNORM`, `ICD10CM`, `HPO`), so the output can be published. The
> `--include-licensed` switch additionally pulls in restrictively licensed
> sources (`SNOMEDCT_US`, `MDR`); a dictionary built that way is a derivative of
> licensed content, is for personal / authorized use only, and **must not be
> redistributed**. See the repository-root `THIRD_PARTY_NOTICES.md`.

> ⚠️ **`UMLS_LOCATION` is hard-coded** at the top of `main.py` to a local
> absolute path. Override it with `--umls-location` on any other machine.
> `MRCONSO.RRF` is ~2 GB; a full run takes minutes and is streamed line-by-line
> (never loaded fully into memory).

## Pipeline overview

`generate()` runs these stages in order (see `main.py`):

1. **Parse** (`parse_line` / `iter_concepts`): `MRCONSO.RRF` is a pipe-delimited
   file; each line becomes a `MetathesaurusConcept`. Streamed with an optional
   `--limit`.
2. **Organism CUI exclusion** (`load_excluded_cuis`): reads `MRSTY.RRF` and
   collects every concept (`CUI`) whose semantic type is in `ORGANISM_TUIS`
   (bacteria, fungi, viruses, plants, animals, …). These taxonomy/species names
   are dropped wholesale in `build_word_set`.
3. **Relevance filter** (`is_relevant`): keeps only **English**,
   **non-suppressed** records, restricts to the **source allow-list**
   (`INCLUDED_SAB`), and drops records whose **term type (`TTY`)** is in
   `EXCLUDED_TTY` (see *Quirks* below).
4. **Word extraction** (`extract_words`): tokenises the concept string, drops
   digits/punctuation/units, and skips biological-sequence / peptide notations.
5. **De-dup against en_US** (`remove_reference_words` +
   `load_reference_words_expanded`): removes any word already coverable by the
   base English dictionary — **including affix-derived forms**.
6. **Case-variant collapse** (`collapse_case_variants`): merges
   `Cytokine`/`CYTOKINE`/`cytokine` onto the lower-case root (capitalised-only
   brand/eponym names are preserved).
7. **Hyphen collapse** (`collapse_hyphenated_words`): drops redundant hyphenated
   compounds whose parts are each independently coverable, relying on Hunspell's
   `BREAK` rules.
8. **Must-have safety net** (`ensure_must_have_terms`): re-adds any curated
   clinical term (`MUST_HAVE_TERMS`) that filtering removed and that the base
   dictionary doesn't already cover.
9. **Plural collapse** (`collapse_plurals`): applies the `medical.aff` `SFX S`
   rule — when a stored plural (`millilitres`) is the regular plural of a stored
   singular (`millilitre`), the plural entry is dropped and the singular is
   tagged `millilitre/S` so Hunspell still accepts both. Matching is
   case-insensitive (`Millimoles` collapses onto `millimole`).
10. **Genitive collapse** (`collapse_genitives`): applies the `medical.aff`
    `SFX M` rule — when a stored possessive (`Towne's`) is the `'s` form of a
    stored base word (`Towne`), the `'s` entry is dropped and the base is tagged
    `Towne/M`. Flags combine with the plural pass, so a word with both forms
    becomes e.g. `Tourette/SM`.
11. **Write** (`write_dictionary`): sorted, de-duplicated, count-header `.dic`
    (head words carry their `/S`, `/M` or combined flag where applicable) + the
    fixed `.aff`.

### Size history (for context)

The list shrank from ~1.05M raw words to ~62k through successive filters:

| Stage / change | Approx. words |
| --- | --- |
| Initial extraction | ~1,049,841 |
| De-dup vs. `en_US` (head words) | ~993,705 |
| Amino-acid / peptide sequence pruning | ~957,941 |
| TTY (term-type) filtering | ~739,140 |
| Affix-expanded `en_US` de-dup + hyphen collapse | ~645,918 |
| Source (`SAB`) allow-list + organism (`MRSTY`) filter + case-collapse | ~62,065 |
| Plural collapse onto singular `/S` forms | ~61,203 |
| **Genitive collapse onto base `/M` forms** | **~60,580** |

The last step is a deliberate ~10× cut (a clinician-focused list, *quality over
raw count*). The two biggest levers were dropping the **NCBI Taxonomy** source
(~377k words of species names) via the `SAB` allow-list and dropping the
**organism semantic types** via `MRSTY` (~25k more obscure species epithets).

## Quirks & gotchas (read before changing anything)

These are the non-obvious behaviours that have accumulated. They are
intentional — changing them will change the output dramatically.

### 1. `medical.dic` / `medical.aff` are *generated artifacts*
Don't hand-edit them. Re-run `main.py` instead. `medical.aff` is written
verbatim from the `AFF_CONTENT` string constant in `main.py` — that string is
the single source of truth for affix rules.

### 2. It is a **supplement**, not a standalone dictionary
Words present in `en_US.dic` are deliberately **removed**. To use it for
spellchecking you must load **both** `en_US` and `medical` together. On its own,
`medical.dic` will flag ordinary English words as misspelled.

### 3. De-dup expands `en_US` affix rules (`load_reference_words_expanded`)
We don't just compare against bare `en_US` head words; we expand its PFX/SFX
rules so derived forms (`unwillingness`, `unwinding`, …) are also recognised as
"already covered" and removed. This is why some words you'd expect to see are
absent — they're reachable from an `en_US` root + affix.

### 4. Hyphenated compounds rely on Hunspell `BREAK`, not storage
`medical.aff` explicitly sets the default `BREAK` table (`-`, `^-`, `-$`).
Hunspell splits an unknown hyphenated word and re-checks each side, so
`cytokine-induced` is accepted from `cytokine` + `induced` **without** storing
the combination. `collapse_hyphenated_words` therefore drops any hyphenated word
whose every part is independently coverable.
**Do NOT add `BREAK 0` to the affix file** — it would disable this and require
storing every combination again.

### 5. Hyphenated words with an un-coverable part are *kept*
e.g. `I-Macroaggregated` — Hunspell can't validate it from its parts, so it
stays. This rule (`all parts coverable`) is what preserves genuinely lexical
hyphenated terms.

### 6. Biological-sequence pruning is heuristic
Three layers in `extract_words`:
- `SEQUENCE_RE` — single-letter chains (`A-T-G-G`, nucleotide/AA).
- `is_amino_acid_sequence` — three-letter codes (`Val-Leu-Asn-Tyr`,
  `Val-Lys-PABC-DOX`); requires ≥2 amino-acid codes that also form the majority.
- `is_peptide_name` — spelled-out acyl/residue chains (`glutamyl-leucyl-…`,
  `glutamyl-tRNA`).
These are heuristics tuned to avoid dropping real words (`well-being`,
`Pro-American`, `phenylalanine`). Edge cases are possible — adjust the
`AMINO_ACID_*` sets if false positives/negatives appear.

### 7. Source (`SAB`) allow-list — the biggest single lever (and the licensing lever)
The source vocabularies are split by **redistribution rights** (in `main.py`):

- **`FREE_SAB`** (the default `INCLUDED_SAB`): freely redistributable sources —
  **`RXNORM`, `ICD10CM`, `HPO`**. The output built from these can be published
  (it ships in the repo under the crate's MPL-2.0 code license).
- **`LICENSED_SAB`**: restrictively licensed sources — **`SNOMEDCT_US`, `MDR`**
  (MedDRA). Enabled only with `--include-licensed`; the resulting dictionary is
  a derivative of licensed content and **must not be redistributed**.

UMLS aggregates ~100 sources; most are low-yield for dictation. The **NCBI
Taxonomy** (`SAB=NCBI`) alone is ~377k species names — excluding it is the
largest cut. Override the set with `--include-sab "A,B,C"`, or `--include-sab
all` for every source. Note that most non-free sources (`MSH`, `NCI`, `LOINC`,
…) carry their own restrictive licenses — check before publishing any output
built from them.

### 8. Organism / taxonomy filter via `MRSTY.RRF`
Even within the allowed sources, `SNOMEDCT_US` carries an *organism* hierarchy
(species of bacteria/fungi/viruses). `load_excluded_cuis` reads `MRSTY.RRF` and
drops every concept whose semantic type is in `ORGANISM_TUIS` (~25k obscure
species epithets like `abactoclasticum`). **Common pathogens survive** because
they also appear in non-organism *disease* concepts (and many genus names like
`staphylococcus`/`streptococcus` are already in `en_US`). Disable with
`--mrsty-file ""`.

### 9. TTY (term-type) filtering
`EXCLUDED_TTY` (in `main.py`) drops ~50 term types that aren't dictatable words:
systematic chemical/CAS names (`CCN`, `CHN`, `CSN`, `N1`), MeSH Supplementary
Concept Record names (`NM`, `CE`, `PCE`), abbreviations/acronyms (`AB`, `ACR`,
…), machine codes/identifiers (`CA2`, `CSY`, …), machine-formatted drug strings
(`CDA`, `CDC`, `CDD`) and obsolete content (`OET`, `OP`, `MTH_O*`, …).
Human-readable types (`PT`, `SY`, `IN`, `PN`, `MH`, `SCN`, drug names…) are
**kept**.

### 10. Case variants are now collapsed (`collapse_case_variants`)
**Changed behaviour.** `Cytokine`/`CYTOKINE`/`cytokine` are merged onto the
lower-case root (Hunspell accepts capitalised forms of a lower-case root for
free). Words that **only ever appear capitalised** (brand names, eponyms,
acronyms like `Tylenol`, `MRSA`) are *kept* in their best single form, so
legitimately-capitalised names are not lost. Disable with
`--keep-case-variants`.

### 11. Must-have safety net (`MUST_HAVE_TERMS` / `ensure_must_have_terms`)
A curated list of essential clinical terms (common diagnoses, procedures,
medications, exam findings) is re-added after filtering if it was pruned **and**
isn't already covered by `en_US`. This guards against aggressive filters
silently dropping a high-yield word as the list keeps shrinking. Extend
`MUST_HAVE_TERMS` when you notice a missing essential term; disable the re-add
with `--no-must-have`. A test asserts every entry is a valid extractable word.

### 12. `models.py` uses the `@dataclass` decorator
An early bug had `MetathesaurusConcept` subclassing `dataclass` instead of being
decorated by it. It's fixed; keep it as `@dataclass`.

### 13. Plurals are collapsed onto `singular/S` (`collapse_plurals`)
The `medical.aff` `SFX S` rule **is now actually applied** at generation time
(it used to be defined but never used). When both a singular and its regular
plural are present (`millilitre` + `millilitres`), the plural entry is dropped
and the singular is written as `millilitre/S`; Hunspell re-expands `/S` so the
plural is still accepted. Matching is case-insensitive, so a capitalised plural
(`Millimoles`) collapses onto a lower-case singular (`millimole`). This is why
some `.dic` head words carry a `/S` flag and their plural forms are absent.
Disable with `--keep-plurals`. The medical and `en_US` `SFX S` rule lines are
intentionally identical so the two dictionaries pluralise consistently.
**`PLURAL_FLAG` (`main.py`) must stay in sync with the flag used in the
`AFF_CONTENT` `SFX` block.**

### 14. Genitives (`'s`) are collapsed onto `base/M` (`collapse_genitives`)
UMLS lists possessive eponyms both ways (`Towne` + `Towne's`, `Tourette` +
`Tourette's`). The `medical.aff` `SFX M` rule (`SFX M 0 's .`, mirroring
`en_US.aff`) is applied at generation time: the `'s` entry is dropped and the
base word is tagged `Towne/M`, so Hunspell re-expands the possessive. Matching
is case-insensitive. The plural and genitive flags **combine** on a single head
word, so a word with both forms is written `Tourette/SM`. This shares the
`_collapse_by_suffix` helper with the plural pass. Disable with
`--keep-genitives`. **`GENITIVE_FLAG` (`main.py`) must stay in sync with the
`SFX M` flag in `AFF_CONTENT`.**

## Advice for next time / possible follow-ups

Ordered roughly by leverage. (The first three from earlier sessions are now
**implemented** — see *Quirks* 7, 8 and 10.)

1. **Tune the `SAB` allow-list / `ORGANISM_TUIS`.** The fastest way to trade
   size for coverage. Re-add `MSH`/`NCI` (≈+70k/+90k) for broader biomedical
   coverage, or trim to `SNOMEDCT_US`+`RXNORM` for an even leaner list. If a
   whole category of obscure terms reappears, prefer a record-level
   (`SAB`/`TTY`/semantic-type) filter over per-token regexes.
2. **Grow `MUST_HAVE_TERMS`.** As filtering tightens, this is the guard rail.
   Whenever review finds a missing essential clinical word, add it here (with a
   test) so future iterations can't drop it.
3. **A second lowercase-only word index.** `MRXW_ENG.RRF` (the UMLS Normalized
   Word Index, field `NWD` = normalised lowercase word) is a ready-made source
   of de-cased single words; could feed a complementary all-lowercase list.
4. **Modest `.aff` expansion.** The plural `SFX S` and genitive `SFX M` are now
   applied (see *Quirks* 13 and 14); the next conservative additions could be
   `-ing`/`-ed` suffixes, each paired with a `collapse_*`-style dedup pass (use
   the shared `_collapse_by_suffix` helper) so derived forms are stored as flags
   rather than separate head words. Keep it small — aggressive affixes cause
   **false accepts** (misspellings silently passing). Pruning, not affixes, is
   the real size lever.
5. **Length / hyphen-count guard for chemical names.** Reject very long tokens
   or tokens with many internal hyphens as a catch-all for IUPAC/systematic
   strings. *Caution:* set the length limit high (e.g. ≥30) — real clinical
   words like `esophagogastroduodenoscopy` (26) must not be dropped.

### General principles
- **Pruning beats affix expansion** for controlling size. A medical supplement
  in the **~50k–150k** range is normal and healthy; large lists are fine for
  Hunspell, but only if they're real words, not noise.
- **Favour record-level (`TTY`/`SAB`) filters over per-token regex hacks** —
  remove the *source* of noise rather than pattern-matching each string.
- **Lean on Hunspell features** (`BREAK`, capitalisation, affixes) instead of
  enumerating every surface form.
- **Always add a test** when adding a filter (see `test_main.py`), and
  **regenerate + report the before/after count** so size changes are visible.
